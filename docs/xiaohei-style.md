# 小黑插画风格包(agent 绘画规范)

> 面向 coding agent:用户要求「小黑 / 手绘 / 怪诞 / 正文配图」风格的动画时,先读本文件
> 再按 `schema.md` 产场景 JSON;配套活例 `xiaohei-example.json`(与本文同目录投递)。

## 结论

小黑 = 用现有协议元素拼装的矢量角色:黑椭圆身体 + 白点眼 + connector 细腿细臂,
标注只用红橙蓝三色文字。它的表现力来自「构图 + 入场编排」,不来自部件数量。
一幕只讲一个核心结构,小黑必须参与该结构的核心动作,不能站边上当装饰。

## 风格 DNA

- 画布纯白:`canvas.bg` 用 `#FFFFFF`;默认灰底会毁掉手绘感。
- 主色只有黑:`#1F1F1F`(身体、手绘框描边、正文文字);不要用纯黑 `#000`。
- 标注限三色:红 `#DC2626` / 橙 `#EA580C` / 蓝 `#2563EB`,一幕内合计不超过 3 处。
- 大量留白:全部元素外接框占画布面积不超过一半;宁缺毋滥。
- 禁止:渐变、阴影堆叠、照片质感、幼稚可爱画风、左侧流程图式布局、
  「流程图 / 架构图 / 常见坑」这类类型标题出现在画面里。

## 小黑画法配方(1920x1080 画布)

一个标准站姿小黑 = 5~7 个元素,直接抄这组坐标再按构图平移缩放:

| 部件 | kind 与字段 | 参考值 |
|---|---|---|
| 身体 | `shape` ellipse,`fill #1F1F1F` | x=830 y=470 w=260 h=195(略扁) |
| 左右眼 | `shape` ellipse,`fill #FFFFFF` | 22x32 两枚,顶部对齐身体上缘,高低差 4~6px 更有神 |
| 左右腿 | `connector` 直线,`arrow:false width:9 color:#1F1F1F` | 从身体下缘向两侧外撇,长约 50px |
| 手臂 | `connector` 直线,同腿 | 指向 / 推 / 举靠端点表达;起点放身体轮廓内 20px 保证「长在身上」 |
| 嘴 | 不画 | 空表情是 IP 特征 |

- 表情 = 眼睛位置:正视、斜看道具、看箭头方向,靠两枚白点的偏移表达。
- 小黑缩小版:整体坐标乘 0.78;多一个小黑 = 复制一组并错开轨道。
- 腿 / 臂的 `x y w h` 填实际包围盒,便于编辑器选中与擦除动画裁剪。

## 部件语法表(手绘感 -> 协议元素)

| 手绘意图 | 用什么 |
|---|---|
| 手绘方框 | `shape` rect 白底 + `stroke #1F1F1F strokeWidth 4 radius 12~16`,文字用独立 `text` 居中叠加 |
| 弧线箭头 | `connector` `curve:-60~-90`(左到右向上弓)`width:5` 橙/红,`arrow` 缺省 |
| 直线箭头 | `connector` `route:"straight"` 同上 |
| 下划线 / 强调圈 | `connector` `arrow:false` 红或橙,直线下划 / 大弧度 curve 圈注 |
| 地面线 | `connector` `arrow:false width:4 color:#E2E2E2` |
| 说话 | `shape` speechBubble 白底黑描边 4 + `text` 叠加 |
| 歪斜批注 | `note` `rotate:3~5`,一幕最多一张 |
| 普通标注 | `text` 红/橙/蓝,fontSize 26~30,贴近被标注物 |
| 大字标语 | `title` 或 `artText`,黑色为主,highlight 芯片替代彩色底 |

## 入场编排(动画即演出)

推荐节奏(相邻元素 start 错开 0.05~0.3s):

```
地面线 fade 0
身体 pop 0.15(0.5~0.6s,回弹缺省)
腿 fade +0.25  眼 fade +0.45(眼最后点上去,像画完一笔)
手臂 pop +0.7
道具 / 对话框 riseUp +0.95
标注 fade 最后(+1.5 左右),文字可用 typewriter 模拟手写
```

- 一幕总时长控制在 3~4.5s,dwell 1.2~1.5。
- `wipe` 按元素 `x y w h` 矩形裁剪,connector 布局不走 w/h,箭头动画用
  `fade` / `pop`,别用 `wipe`。
- 协议只有入场动画:小黑在幕内不走位,「走」靠换幕换位 + 相邻幕构图连续;
  部件逐个入场本身就是小黑味的核心(像被一笔一笔画出来)。

## 构图模式(从主题挑认知锚点)

每幕只选一种,从一个核心判断出发重新发明隐喻,不复刻任何已有构图:

- 单主体 + 标注:小黑做一件荒诞但成立的事,三色标注点睛(开场 / 收尾幕)。
- 承接路径:左进右出,小黑居中加工,弧线箭头衔接(流程 / 转化主题)。
- 前后对比:左旧右新,小黑站在「新」一侧发力(方法对比主题)。
- 分流:小黑在岔口指向正确支路(选择 / 取舍主题)。
- 循环闭环:小黑推着元素绕一圈回到起点(迭代 / 反馈主题)。
- 常见坑:地面线开缺口,小黑跨过去(避坑主题)。

选题优先级:核心判断 > 认知转折 > 状态变化;不平均配图,一支撑 3~6 幕即可。

## 交付前自查

1. 小黑是否在执行核心动作(而不是站立装饰)?
2. 画布是否纯白、元素是否过满(>50% 面积即删)?
3. 是否太像流程图 / PPT(方框直角连线平铺即超限)?
4. 标注是否只用红橙蓝且不超过 3 处?类型标题是否混进画面?
5. 每幕是否只讲一个结构?入场顺序是否符合「身体 -> 眼 -> 道具 -> 标注」?
6. `pnpm anim validate` 是否通过且警告清零?

## 边界(如实告知)

- 协议无手写字体,标注用系统黑体近似;手绘感靠构图、留白与三色标注,不靠字体。
- 无旋转的 ellipse 身体是正椭圆,「怪诞感」靠眼睛高低差、外撇腿与场景隐喻补偿。
- 需要照片级或复杂插画时,走 `image` 元素外挂素材,不要用小黑硬画。
